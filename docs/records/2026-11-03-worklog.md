## 4. 关键决策与依据

### 4.1 不 fork frp（独立仓库）

依据：

- frp 是 Apache-2.0，允许二次分发；不改源码时义务最轻
- 我们需要的所有能力（状态、热重载、配置读写）frpc 已经通过管理 API 暴露：`/api/status`、`/api/reload`、`/api/config`、`/api/store/proxies`
- QNAP 外壳（打包脚本、QTS 代理路径、启动脚本、前端）对上游零价值，PR 不可能被接受，fork 只会长期背 diff
- 升级路径：改一行 `FRP_VERSION` + 重跑 CI；fork 则每次 release 都要 rebase

**例外条件**：只有必须改内核行为时才 fork，且用 `patches/` + `git apply`，patch 数控制在个位数。

### 4.2 frpc 用官方二进制 sidecar（不做 Go 内嵌）

- 优点：与上游行为完全一致、升级零成本、CI 只编自己的代码
- 代价：两个进程，manager 需要做进程守护（已实现退避重启）
- 内嵌（`import github.com/fatedier/frp/client`）留作 v2，用 build tag 隔离；收益是单进程、可直接拿 `svc.Status()`

### 4.3 manager.json 是唯一真相源

- `frpc.toml` 每次保存重新生成（旧版备份 `.bak`）
- 好处：后端不需要 TOML 解析器 → **零第三方依赖**（连 `BurntSushi/toml` 都没引）
- 代价：用户手工改 TOML 会在下次保存时被覆盖，README 已声明

### 4.4 前端不用框架、不做构建

- 四页规模，原生 ES 模块足够
- 打包链不需要 Node；QPKG 里直接放静态文件；改文件刷新即生效
- 相对路径 + hash 路由，天然兼容 QTS 反代的子路径

### 4.5 状态与生效策略

| 变更类型 | 动作 | 依据 |
|---|---|---|
| 代理增删改 | `GET /api/reload` | frp 热重载只重建代理，其他隧道不断 |
| `serverAddr/serverPort/auth/transport/log` | 重启进程 | frp 的公共段不支持热重载 |
| 保存前 | `frpc verify -c` | 用上游校验器，避免自写规则漏字段 |

## 5. 验证数据

### 5.1 端到端（`scripts/e2e.sh`）

环境：macOS arm64 + frp 0.71.1 darwin/arm64（frpc + frps 本地互连）。

连续两轮结果：**23 通过 / 0 失败**。

覆盖清单：

1. 健康检查、首页 200、页面含应用标识
2. 初始口令登录成功、错误口令 401
3. 未登录访问 API 401、缺 CSRF 头 403
4. 首次保存后 frpc 启动、未触发重启
5. 生成的 TOML 含 `remotePort`、含 `[[proxies]]`
6. 隧道状态上报 `running`、概览统计 2 条运行中
7. 新增代理触发热重载（不重启进程）
8. 改日志级别触发重启
9. 非法配置被拒绝（提示"远程端口"）且不覆盖旧配置
10. 日志可读、`/frpc-qnap` 前缀两种访问均 200
11. 停止/启动接口生效

### 5.2 界面

Playwright + 系统 Chromium（1100×640，2x），实际登录操作：

- 概览：徽章"1 条隧道异常"、统计 `2/3`、"1 条异常"、错误行标红 —— 与实际 frpc 状态一致
- 隧道页：表格、备注副行、编辑/删除按钮
- 弹窗：选 HTTP 类型后自动隐藏"远程端口"、显示域名相关字段
- 设置页：三张卡（服务器/传输/日志）对齐，Token 显示"已设置，留空不修改"
- 控制台：**零报错**（修掉 favicon 404 后）

## 7. 本轮未验证 / 存疑

| 项 | 风险 | 影响 |
|---|---|---|
| `qbuild` 从未执行 | 中 | 首次打包可能因目录约定报错，需现场调 |
| QTS 代理是否剥离 `/frpc-qnap` 前缀 | 中 | 后端已兼容两种，但要确认 cookie path / 重定向是否正确 |
| 固件升级后代理配置是否自愈 | 中 | 走官方 `QPKG_USE_PROXY` 机制应自愈，需实测 |
| `QPKG_DESKTOP_APP=1` 的 iframe 是否被 CSP 拦 | 低 | 若失败退化为 `0`（新标签页） |
| 7911 端口在目标机型上是否被占 | 低 | 目前硬编码，需加顺延逻辑 |
| arm64 真机性能（frpc + manager 常驻） | 低 | 预期 < 50 MB 内存 |
