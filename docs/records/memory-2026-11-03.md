# 2026-11-03

## frpc-qnap 方案评估（新建项目）

- 目标：QNAP 原生 QPKG 封装的 frpc，支持 x86_64 + arm_64，管理界面嵌进 QTS 网页端（不额外开端口）。
- 产出：`docs/frpc-qnap-方案评估.md`（v0.1 评估稿）。
- 核心结论：
  - 仓库策略：**独立仓库，不 fork frp**（QNAP 外壳代码对上游零价值；升级只需 bump FRP_VERSION 换二进制）。仅在必须改内核时才用 `patches/` + 临时 fork。
  - 不开端口的机制：`QPKG_WEBUI` + `QPKG_WEB_PORT` + `QPKG_USE_PROXY=1` + `QPKG_PROXY_PATH`，由 QTS Apache 反代；`QPKG_DESKTOP_APP=1` 让它在 QTS 桌面弹窗；`QPKG_VISIBLE=1` 进主菜单。
  - frpc 复用方式选 **官方 release 二进制 sidecar**（v1），Go 模块内嵌留 v2；因为 frpc 已有 `/api/status`、`/api/config`、`/api/reload`、`/api/stop`、`/api/store/proxies`，且 `frpc verify` 可做保存前校验。
  - 必须自研前端：frpc 自带 dashboard 是绝对路径资源的 Vue SPA，子路径反代必 404。
  - 双架构：`qbuild --build-arch x86_64|arm_64`，可重复传参做单包多架构（P4 再试）；架构探测 x86_64→x86_64、aarch64→arm_64。
- 关键事实核对：
  - frp v0.71.1（2026-10-14），Apache-2.0。
  - QTS 5.0.1 起 App Center「允许安装不具数字签名的应用」默认关闭；自签名过不了 QNAP 信任链，走官方签名需合作方资质。
  - QPKG_NAME 不要用 `frpc`（App Center 按名字判重，会与 2019 民间包冲突），用 `frpc-qnap`。
- 待实测（Phase 0）：QTS 代理是否剥离 `/frpc-qnap` 前缀；`/etc/config/apache/extra/` 生成物内容；重启与固件升级后代理是否自愈；桌面 iframe 是否有 CSP 限制。
- 下一步：等用户拍板 §11 的 D1–D7（尤其 D1 仓库策略、D4 单包/双包、D7 测试机型），然后做 Phase 0 尖刺。

## 原型已落地（同日 11:30）

用户决策：只有 arm64 机器；**每架构一个包且固定如此**；UI 参考 luci-app-frpc 字段；仓库 https://github.com/zeisscai/frpc-qnap.git。

已推送两个 commit（`8d75a35`、`4eeb700`），27 个文件 ~4900 行。

实现要点：
- Go 管理器（零第三方依赖）：`internal/config` 管配置与 TOML 生成，`supervisor` 守护 frpc，`frpc` 包封装 admin API，`server` 管路由/认证/前缀兼容。
- 前端原生 ES 模块（**不用 Vue，无需 Node 构建**），四页：概览/隧道/设置/日志；`base` 相对路径 + hash 路由，天然兼容 QTS 子路径。
- QPKG：`package/qpkg.cfg`（QPKG_USE_PROXY=1、QPKG_DESKTOP_APP=1、QPKG_PROXY_PATH=/frpc-qnap）、`package_routines`、`shared/frpc-qnap.sh`、`icons/frpc-qnap.png`（make-icon.py 生成）、`config/{manager,state}.json` 空模板进 QPKG_CONFIG 保证升级保留。
- 打包：`make arm64`（curl 下载 frpc + sha256 校验 + 交叉编译），`make qpkg` 需 Linux + QDK（本机 macOS 无 Docker/qbuild，**未验证 qbuild**）。

踩过的坑（都已修，写进方案文档 §12.3）：
- frpc `/api/reload` 成功时返回 200 + **空 body**，按 JSON 解析会误判失败 → 不解析响应体。
- `/` 改写成 `/index.html` 交给 FileServer 会 301 循环 → 改用 `http.ServeFileFS`。
- frp 默认 `loginFailExit=true`，frps 不可达时反复退出 → 项目默认 false。
- frpc 状态值有 `start error` 这类组合值 → 用 `strings.Contains(status,"error")` 计数。
- macOS AirPlay 占 7000 → e2e 改用 17000/28080。

验证：`scripts/e2e.sh` 拉起本地 frps，23 项断言连续两轮全绿；UI 用 Chromium(headless)+playwright-core 截图确认（概览 2/3 running、弹窗、设置页），控制台无报错。

待办：真机 Phase 0（QTS 代理前缀/桌面窗口/重启自愈/未签名安装）、改密页、visitors、manager 端口顺延。
